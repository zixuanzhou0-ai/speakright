# Maintainers

## Public point of contact

The current public repository owner and primary maintainer contact is [`@zixuanzhou0-ai`](https://github.com/zixuanzhou0-ai). Repository access, merge authority, and release authority are determined by current GitHub permissions, not by commit count or a name appearing in history.

No response-time guarantee is published. Use the narrowest route so a report reaches the right review path:

- general support and issue routing: [`SUPPORT.md`](SUPPORT.md)
- contribution process: [`CONTRIBUTING.md`](CONTRIBUTING.md)
- private vulnerability or credential report: [`SECURITY.md`](SECURITY.md)

## Maintainer responsibilities

- Keep public feature, language, release, and validation claims aligned with source evidence.
- Review security, privacy, dependency, and provider-permission changes proportionally to risk.
- Preserve the stable-English/experimental-language boundary until evidence supports a change.
- Require source and license review for bundled media.
- Prevent routine validation from silently spending paid TTS/provider quota.
- Keep releases, changelog entries, known limits, and rollback information reviewable.

## Decision process

Small reversible changes may be merged after focused review and relevant checks. Changes to scoring authority, private-data handling, bundled assets, external network origins, paid generation, language maturity, or public release status require explicit maintainer review and written evidence.

Conflicts of interest, uncertain licenses, disputed pronunciation evidence, and user-safety concerns should be recorded rather than resolved by guesswork. A maintainer may defer a change when the evidence is insufficient.

## Adding or removing maintainers

Changes to maintainer status should be proposed publicly when privacy and security allow, explain the expected scope, and update this file plus `.github/CODEOWNERS` in the same pull request. Private contact details and application-account information must not be added here.
